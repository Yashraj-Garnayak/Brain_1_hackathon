# TILE RUSH — Cloudflare Worker + Durable Objects

Realtime edge layer for TILE RUSH 1v1. The REST API keeps running on
Vercel/Neon; this Worker serves the static client, proxies `/api/*` to the current
API origin, and owns matchmaking and match rooms.

## What is here

| File | Purpose |
| --- | --- |
| `wrangler.toml` | Worker config, assets binding, DO bindings + migration |
| `src/index.js` | Router: health, queue, match socket, API proxy, static assets |
| `src/ticket.js` | Verifies the Vercel-signed match ticket (HMAC-SHA256) |
| `src/queue-room.js` | Global matchmaking queue keyed by account id |
| `src/match-room.js` | Hibernating WebSocket Durable Object for one 1v1 match or room (two players + read-only spectators) |
| `public/` | Generated by `npm run worker:assets` — never commit it |

## Run locally

```bash
npm install
npm run worker:assets        # copies index.html, css/, js/, shared/ into worker/public
npm run worker:dev           # wrangler dev on http://localhost:8787
```

Create `worker/.dev.vars` (gitignored) with the same secret the local Vercel API
mints:

```
MATCH_SECRET=<same value as .env.local>
```

Set `MATCH_URL=http://127.0.0.1:8787` in `.env.local` for local play; `vercel dev`
needs the variables exported in its shell if it does not pick them up:

```bash
export $(grep -E '^MATCH_(SECRET|URL)=' .env.local | xargs)
npx vercel dev
```

`worker:assets` exists so Wrangler uploads only the site. Do not point the assets
directory at the repo root; `.env.local` lives there.

## Deploy

The **Workers Free plan is enough**. Durable Objects with the SQLite backend
(what `wrangler.toml` declares via `new_sqlite_classes`) are available on free,
and static assets are not counted against the Worker request quota.

```bash
npx wrangler login                        # free Cloudflare account, one time
npm run worker:check                      # dry-run bundle, validates config + DO classes
printf '%s\n' "$MATCH_SECRET" | npx wrangler secret put MATCH_SECRET --config worker/wrangler.toml
npm run worker:deploy                     # https://<worker>.<subdomain>.workers.dev
```

Free-tier limits that matter here:

| Resource | Free allowance | What it means for TILE RUSH |
| --- | --- | --- |
| Worker requests | 100,000 / day | API proxy + queue polls; static files are free |
| Worker CPU | 10 ms / invocation | the router and DO handlers are far below this |
| DO requests | 100,000 / day | incoming WebSocket messages bill at 20:1 |
| DO duration | 13,000 GB-s / day | hibernation makes idle matches free |
| SQLite rows | 5M read / 100k written per day | writes happen on join/ready/finish, not progress |
| DO storage | 1 GB per object, 5 GB total | match state is a few KB |

A 60-second match with two players costs roughly 150 WebSocket messages and
about 8 GB-s of active time, so one free account covers hundreds of matches a
day. Exceeding a free limit fails the operation; it never produces a bill.

`uday.live` is on Vercel DNS, not Cloudflare, so use a `workers.dev` hostname
rather than a subdomain of `uday.live`. Keep the REST API on Vercel, mint a
short-lived signed match ticket there (`POST /api/match/ticket`) and pass it to
the Worker — cookies cannot cross to a different hostname.

The Worker is stateless for accounts; sessions and runs still live in Neon.
`API_ORIGIN` in `wrangler.toml` points at the Vercel deployment.

## Realtime protocol

Matchmaking is a poll, not a socket. Every request carries the signed ticket:

```
POST /api/match/queue
  { "ticket": "<payload>.<hmac>" }
  -> { waiting: true, position: 1 }
  -> { matchId: "…", waiting: false }          # ran after the second player joins
```

The ticket payload is `{ v: 1, uid, name, role, exp }`; `MATCH_SECRET` is shared
by Vercel and the Worker. Missing, expired or tampered tickets get `401`. A
`spectator` ticket is read-only; the Worker never lets it claim a player slot,
and the queue endpoint rejects it with `403 players_only`.

Then both players open the socket with the same ticket:

```
GET /api/match/:id/ws?ticket=<payload>.<hmac>
GET /api/match/:id/ws?ticket=…&role=spectator&mode=room
```

The Worker verifies it and forwards the identity to the Durable Object as
`x-tr-uid` / `x-tr-name` / `x-tr-role` / `x-tr-kind` / `x-tr-room`; the socket
auto-joins as that account. Client-supplied names are never trusted.

A match id beginning with `room-` (or `mode=room`) is a private room. A room
accepts two players and up to 20 spectators; the first two player sockets get
the slots, and a third player is automatically seated as a spectator
(`state.spectator = true`, `state.auto = true`). Spectators may only send
`ping` or `join`; every other message gets `{ type: 'error', code: 'read_only' }`.

| Client → server | Server → client |
| --- | --- |
| `{ type: 'ready', ready: true }` | `{ type: 'state', you, match, spectator? }` |
| `{ type: 'progress', round, correct, score }` | `{ type: 'peer', player }` |
| `{ type: 'finish', score, bpi }` | `{ type: 'countdown', round, startsAt, seed }` |
| `{ type: 'emote', id }` | `{ type: 'progress', from, round, correct, score }` |
| `{ type: 'rematch' }` | `{ type: 'emote', from, id }` |
| `{ type: 'ping' }` | `{ type: 'result', winner, players }` |
| `{ type: 'join' }` (no-op echo) | `{ type: 'peer_left', player }` / `{ type: 'spectators', count }` / `{ type: 'pong', now }` |

Allowed emotes: `gg`, `wave`, `nice`, `oops`, `focus`, `rematch`.

The room starts a 3-second countdown once both players send `ready`, and includes
the match `seed`. Clients generate board *n* of a round from
`hash(seed, round, n)`, so both players face the same ordered layouts. Scores are
clamped, messages are capped at 4 KB, and only whitelisted emotes are relayed.
Rematch resets the room with a fresh seed.

## Known limits

1. Scores are client-reported. They are clamped and both runs are separately
   validated by `/api/runs`, but a determined client could still inflate a score.
   The next step is a signed per-run token or server-side replay.
2. Queue joins rely on the ticket TTL (10 minutes) rather than a per-user rate
   limit. Entries expire from the queue after two minutes.
3. The room clock starts both clients together, but rounds and breaks run locally
   on each client. Server-authoritative round timing would be the next upgrade.
